# TextSieve

[English](README.md) | Русский

TextSieve — детерминированный фильтр качества и безопасности текста для JavaScript и TypeScript. Он обнаруживает явные оскорбления, консервативно распознаёт обфускацию, подозрительный Unicode, спамоподобное оформление и базовые признаки бессмысленного текста без ИИ, удалённых API, телеметрии и сетевых запросов.

Проект активно развивается. Текущие словари намеренно невелики и пока не подходят на роль единственного уровня модерации в production-сервисе.

## Требования к среде выполнения и разработке

- Node.js 20 или новее для использования библиотеки
- Node.js 24 LTS и npm 11 для разработки в репозитории

Совместимость с Node.js 20 постоянно проверяется, но сама Node.js 20 больше не поддерживается разработчиками платформы. Для production-развёртываний выбирайте актуальную LTS-версию.

Публикуемые пакеты используют ESM и не имеют runtime-зависимостей.

В ветке 0.1.x публикуются только ESM-пакеты. В Node.js необходимо использовать `import`; CommonJS `require()` не поддерживается.

## Использование

```bash
npm install @textsieve/core @textsieve/ru @textsieve/en
```

```ts
import { createSieve } from "@textsieve/core";
import { en } from "@textsieve/en";
import { ru } from "@textsieve/ru";

const sieve = createSieve({
  languagePacks: [ru, en],
  expectedLanguage: "ru",
  safetyLanguages: ["ru", "en"],
  transliteration: {
    enabled: true,
    targets: ["ru"]
  },
  preset: "public-form"
});

const result = sieve.inspect("ах ты bitch");

console.log(result.decision); // reject
console.log(result.issues);   // исходные диапазоны и метаданные совпадений
```

`expectedLanguage` управляет сигналом несоответствия ожидаемому языку. `safetyLanguages` независимо определяет, какие словари нежелательной лексики применяются. Латинские технические термины в русском тексте сами по себе не приводят к отклонению.

## API

- `inspect(text)` возвращает полный неизменяемый результат проверки.
- `check(text)` возвращает `true`, только если решение равно `allow`.
- `normalize(text)` возвращает производное представление после NFKC-нормализации и приведения к нижнему регистру.
- `sanitize(text)` дополнительно удаляет небезопасные управляющие символы и схлопывает пробелы.

Позиции `start` и `end` в проблемах — полуинтервалы UTF-16 в исходной строке `input`, даже если совпадение найдено через производный вариант токена.

## Безопасность и конфиденциальность

TextSieve не выполняет сетевые запросы и не отправляет телеметрию. Исходный текст остаётся внутри процесса приложения.

Проверка в браузере служит только для удобства пользователя. Любое решение, влияющее на доступ, необходимо повторить на доверенном сервере с той же версией и конфигурацией.
