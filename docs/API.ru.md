# API TextSieve

[English](API.md) | Русский

Установите полный RU/EN-дистрибутив и импортируйте публичный API из единой точки входа:

```bash
npm install textsieve
```

```ts
import { createSieve, en, ru } from "textsieve";
```

Если нужен только отдельный модуль, по-прежнему можно установить соответствующий пакет из пространства `@textsieve`.

## `createSieve(options)`

Создаёт изолированный детерминированный инспектор. Языковые пакеты регистрируются явно, а их данные копируются и фиксируются в момент создания.

```ts
const sieve = createSieve({
  languagePacks: [ru, en],
  expectedLanguage: "ru",
  safetyLanguages: ["ru", "en"],
  transliteration: { enabled: true, targets: ["ru"] },
  preset: "public-form"
});
```

`expectedLanguage` влияет только на проверку соответствия языка. `safetyLanguages` независимо выбирает пакеты, применяемые для проверки безопасности.

## Методы

### `inspect(text)`

Возвращает решение `decision`, оценку качества `score`, исходный и производные тексты, нормализованные проблемные сигналы `signals`, объяснимые проблемы `issues` и детерминированные метаданные. Позиции проблем — полуинтервалы UTF-16 в исходной строке.

### `check(text)`

Возвращает `true`, только если `inspect(text).decision` равно `allow`.

### `normalize(text)`

Возвращает представление после пографемной NFKC-нормализации и приведения к нижнему регистру. Подозрительные символы не удаляются.

### `sanitize(text)`

Возвращает отдельное производное представление, из которого удалены небезопасные управляющие символы и в котором схлопнуты пробелы.

## Предустановки

`lenient`, `public-form`, `comment`, `username` и `strict` экспортируются через `presets` как обычные неизменяемые конфигурации.

## Ограничения входных данных

Выбранная предустановка задаёт максимальную длину входной строки в кодовых единицах UTF-16. Слишком длинный текст отклоняется с `INPUT_TOO_LONG` и не проверяется частично.

Предустановки также ограничивают число возвращаемых проблем и вариантов токенов. `meta.totalIssueCount` содержит число проблем до ограничения, а `meta.issuesTruncated` показывает, был ли публичный список сокращён.

## Пользовательские правила

Пользовательское правило должно быть детерминированным, не иметь побочных эффектов и обладать уникальным непустым ID. Оно возвращает конечную проблемную оценку от 0 до 1. Правила получают неизменяемый `RuleContext` и не выбирают итоговое решение напрямую.
